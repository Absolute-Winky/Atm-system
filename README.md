# ATM System

Учебный проект по многослойной архитектуре: серверная часть системы банкомата на C# и ASP.NET Core. Реализованы операции со счетами, сессии пользователей и администраторов, история операций и тесты бизнес-логики.

## Возможности

- Администратор может открыть сессию по системному паролю и создать счёт.
- Пользователь входит по номеру счёта и PIN-коду.
- В пользовательской сессии доступны просмотр баланса, пополнение, снятие средств и история операций.
- Некорректные суммы и недостаток средств обрабатываются как ошибки. Доступ к операциям проверяется по ключу сессии.

## Архитектура

Бизнес-логика зависит от интерфейсов репозиториев. Реализации хранилищ и HTTP-контроллеры подключаются отдельно через Microsoft.Extensions.DependencyInjection.

```text
src/
  Lab5/                            — Web API и точка входа
  Lab5.Application/                — сервисы счетов и сессий
  Lab5.Application.Abstractions/   — интерфейсы репозиториев
  Lab5.Application.Contracts/      — контракты сервисов и результаты операций
  Lab5.Application.Models/         — счета, сессии и операции
  Lab5.Infrastructure.DataAccess/  — in-memory репозитории
tests/
  Lab5.Tests/                      — модульные тесты бизнес-логики
```

## Сборка и тесты

Нужен .NET SDK 9. Версия и правило выбора SDK указаны в `global.json`.

Из корня репозитория:

```shell
dotnet restore AtmSystem.sln
dotnet build AtmSystem.sln --configuration Release --no-restore
dotnet test AtmSystem.sln --configuration Release --no-build
```

Тесты написаны на xUnit с моками репозиториев через NSubstitute. Проверяются успешное снятие, отказ при недостаточном балансе и пополнение счёта.

## Запуск API

Перед запуском задайте системный пароль администратора через переменную окружения `AdminAuth__SystemPassword`. Приложение не запускается с пустым паролем. Значение ниже — только пример для локального знакомства с проектом.

PowerShell:

```powershell
$env:AdminAuth__SystemPassword = "local-demo-password"
dotnet run --project src/Lab5/Lab5.csproj --no-launch-profile --urls http://localhost:5000
```

Bash:

```bash
AdminAuth__SystemPassword='local-demo-password' dotnet run --project src/Lab5/Lab5.csproj --no-launch-profile --urls http://localhost:5000
```

После запуска откройте [Swagger UI](http://localhost:5000/swagger) в браузере. В нём можно отправлять запросы через **Try it out** и **Execute**: сначала открыть административную сессию, скопировать `sessionKey` из ответа и создать счёт. Затем открыть пользовательскую сессию и использовать её ключ для операций со счётом. Системный пароль вводится в запросе входа администратора, ключ сессии — в JSON-поле `sessionKey` нужной операции.

Также доступны примеры в [requests.http](requests.http). Их можно выполнять последовательно в расширении REST Client для VS Code: ключи сессий подставляются из ответов на запросы входа. При повторном создании того же счёта API вернёт ошибку — измените номер или перезапустите приложение.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/sessions/admin` | Открыть административную сессию |
| POST | `/api/accounts/create` | Создать счёт |
| POST | `/api/sessions/user` | Открыть пользовательскую сессию |
| POST | `/api/accounts/deposit` | Пополнить счёт |
| POST | `/api/accounts/withdraw` | Снять средства |
| POST | `/api/accounts/balance` | Посмотреть баланс |
| POST | `/api/accounts/history` | Получить историю операций |
| DELETE | `/api/sessions/{sessionKey}` | Закрыть сессию |

Ошибки доступа возвращают `401 Unauthorized`, некорректные операции — `400 Bad Request`.

## Ограничения учебной реализации

Данные хранятся в памяти и теряются после перезапуска. SQL и постоянное хранилище не используются. PIN-коды и пароль обрабатываются в упрощённом виде; проект не предназначен для работы с реальными банковскими данными.
